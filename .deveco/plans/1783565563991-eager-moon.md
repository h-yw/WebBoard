## 修复方案

### Goal

修复导入本地 HTML 文件后在 Viewer 中打开空白的问题。根因是持久化授权路径中 Picker URI 已含 `file://` 前缀，而 `ViewerPage.getWebSrc()` 又无条件添加一次，形成 `file://file://...` 的无效路径。

### Scope / Non-goals

- **Scope**: 仅修复 ViewerPage / ImportPage / Index 三处与路径处理相关的逻辑
- **Non-goals**: 不涉及网络导入、预设应用、UI/UX 等其它模块

### Current State And Constraints

1. `FileManager.tryPersistPermission()` 成功时，`entryHtml` 被存为原始 Picker URI（如 `file://docs/storage/Users/.../file.html`）
2. `ViewerPage.getWebSrc()` 对所有非 rawfile/非 URL 路径执行 `'file://' + entryHtml`，导致双重 `file://` 前缀
3. `Index.deleteApp()` 对 FILE 类型执行 `fs.accessSync(entryHtml)`，但 Picker URI 不是可解析的文件系统路径
4. ArkTS 严格模式：不能使用 `any`、`as` 断言，需使用正确的类型标注

### Design

**Fix 1 — ViewerPage.getWebSrc()**：添加对已有 `file://` 前缀的检测，直接返回。

**Fix 2 — ImportPage.handleSave()**：持久化成功时，从 Picker URI 中去除 `file://` 前缀后再存储，保持与沙箱路径一致的格式（无 scheme 前缀）。

**Fix 3 — Index.deleteApp()**：当 `persistMode` 非空时跳过文件系统删除操作（原文件属用户所有，不应删除）。

### Key Files

- `entry/src/main/ets/pages/ViewerPage.ets` — `getWebSrc()` 方法
- `entry/src/main/ets/pages/ImportPage.ets` — `handleSave()` 中持久化路径处理
- `entry/src/main/ets/pages/Index.ets` — `deleteApp()` 中跳过持久化文件删除

### Execution Sequence

1. **Fix ViewerPage** (`entry/src/main/ets/pages/ViewerPage.ets`): 修改 `getWebSrc()` 方法，在 `isUrlSource()` 检查之后、`'file://' + entryHtml` 之前，增加对 `entryHtml.startsWith('file://')` 的判断，直接返回 `entryHtml` 本身。

2. **Fix ImportPage** (`entry/src/main/ets/pages/ImportPage.ets`): 在 `handleSave()` 中持久化成功分支（line 139–143），对 `this.selectedFileUri` 去除 `file://` 前缀后再赋值给 `destPath`，确保存储路径格式一致。

3. **Fix Index** (`entry/src/main/ets/pages/Index.ets`): 在 `deleteApp()` 中的 `if (item.sourceType === SourceType.FILE && !item.entryHtml.startsWith('rawfile://'))` 条件内，增加对 `item.persistMode.length > 0` 的排除，跳过文件删除。

4. **Build** (`build_project`): 编译验证无错误。

5. **Verify**: 通过 `start_app` 部署后手动验证：导入本地 HTML → 打开正常显示；URL 导入 → 正常加载；预设应用 → 正常显示；删除持久化文件 → 无崩溃。

### Verification

| 步骤 | 方法 | 预期 |
|------|------|------|
| 编译检查 | `build_project` | 0 错误 |

| 预设应用 | 添加预设 → 打开 | 正常显示 |
| URL 导入 | 输入 URL → 导入 → 打开 | 正常加载网页 |

| 删除沙箱文件 | 删除之前复制到沙箱的应用 | 正常删除 |

### Risks And Compatibility

- 对已有数据无影响，仅影响新导入的文件路径处理
- 项目中已有的旧数据（升级前导入的）路径格式是沙箱路径，不受 ImportPage 更改影响
- ViewerPage 的修复对所有路径类型都有防御作用
