# 新建踩坑记录文档

## Goal

在 `docs/` 目录下新增一篇文档，记录本次排查 Radio 组件 `.onChange()` 导致设置状态不持久化的问题和经验教训。

## File

新建 [docs/arkts-pitfalls.md](docs/arkts-pitfalls.md)

## Content

按项目现有文档风格（中文、Markdown 表格、代码示例），记录：

1. **问题现象**：设置页面外观选项设置后返回再进，先显示正确值后闪烁恢复默认
2. **根本原因**：Radio 的 `.onChange()` 在 `checked` 属性程序化变更时也会触发，且原代码忽略了回调参数直接写死值
3. **排查过程**：从 preferences 存储 → async 生命周期 → Radio onChange 逐步缩小范围
4. **正确做法**：使用 `.onClick()` 替代 `.onChange()` 处理用户交互
5. **对比表格**：Toggle vs Radio 的行为差异
